### 维护期约束

1. **规则唯一来源不变。** 项目规则只在 [`AGENTS.md`](../AGENTS.md)，工作区规则只在 [`../AGENTS.md`](../../AGENTS.md)。不得在本仓库新增任何代理专属的规则文件或目录（例如 `CLAUDE.md`、`.claude/`）；需要新增规则时，直接修改 `AGENTS.md`。
2. **不引入接手方跑不了的流程。** 提交前的全部验证必须能用 `AGENTS.md` 的《本地验收清单》离线完成。不得把编辑器插件、MCP 工具、网络服务或任何特定代理的能力变成必需环节；受限沙箱中 `gh` 失败属于已知假失败，判定方式见工作区规则。
3. **长期结论只进正式记录。** 结论必须落在 `main` 上的 Pull Request、[`CHANGELOG.md`](../CHANGELOG.md)、[`PROJECT.md`](../PROJECT.md)、[`TODO.md`](../TODO.md) 和本文件里，不得只留在聊天或任一代理的本地记忆中。
4. **边界与门禁一律不变。** 源码与产物边界、安全红线、公开仓库边界和发布流程不因维护方更换而调整；生成物只由 `tools/build-cn-entry-role.sh` 和 `tools/build-single-file.sh` 生成。
5. **改动小而单一。** 每次会话只做一件事，走分支加 Pull Request，行为改动必须附带验收测试，提交前跑完整本地验收清单。

### 真机只读验证授权：2026-08-17

项目所有者授权维护方登录其一台**生产**国外出口机执行只读验证，用于确认发布产物在真实环境的行为。授权范围与边界：

- **默认只读。** 只运行不改变持久状态的检查（如 `po0 check`、`po0 status`、`po0 diagnose`、只读的 `systemctl`／哈希核对）。任何可能中断服务、写配置、改权限或不可逆的操作，仍须按次单独取得所有者授权。
- **不动已安装脚本。** 验证新版本时把发布产物作为候选副本放到 `/tmp` 单独运行，验证前后核对已安装脚本的 SHA-256 必须一致，结束后删除候选副本并确认无临时残留。只读子命令（`check`、`self-test`、`__extract-role`）不参与已安装脚本接管，因此候选副本不会顶替线上脚本。
- **线上版本升级由所有者自行执行**，维护方不代为运行更新或回滚。
- **仓库内不写入任何可定位信息。** 服务器地址、端口、账号、密钥与主机指纹一律不进本仓库；这台机器在仓库中只以“项目所有者授权的一台生产国外出口机”指代，连接信息只存在于所有者本地的个人服务器资产清单。

该授权是长期的，适用于后续迭代；它不改变上方任何维护期约束，尤其不使真机成为提交前门禁的一部分——《本地验收清单》仍必须能完全离线完成，接手方没有这台机器也能通过全部门禁。
